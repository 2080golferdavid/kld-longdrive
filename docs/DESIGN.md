# KLD LONG DRIVE — 8비트 장타 골프 게임 설계서

> 상태: v0.3 (구현·리뷰·난이도 조정 반영). v0.1 초안을 조사 1건과 설계 비평 3건(종목 고증 / 아케이드 손맛 / 모바일 홍보 UX)으로 고쳤고,
> 구현 뒤 코드 리뷰 4관점(발견 → 반증 검증)과 봇 시뮬레이션으로 결함과 난이도를 손봤다.
> 조정하는 숫자는 `js/config.js`에 있고, 난이도 관련 값은 `tests/balance.js`의 봇 시뮬레이션으로 맞춘다.
> (예외: 돌풍 시간표와 탑볼·뽕샷 수치는 `js/shot.js`, 히트스톱·몸풀기 보정은 `js/game.js`에 있다.)

## 1. 한 줄 요약

실제 장타 대회 형식(세트당 6구 · 2분 30초 · 그리드 안에 멈춘 최장 기록만 인정)을
**탭 세 번**(스윙 시작 → 파워 → 임팩트)으로 즐기는 8비트 스타일 웹 게임.
KLD(한국장타협회, Korea Long Drive) 홍보·이벤트용으로 공개하는 것이 목적이다.

## 2. 사용자 확정 사항 (변경 불가)

| 항목 | 결정 |
|---|---|
| 조작 | 타이밍 게이지 — 파워 결정, 그다음 임팩트 타이밍 (빠르면 훅 / 늦으면 슬라이스) |
| 구성 | 대회 토너먼트 — 세트당 6구·제한시간, 그리드 안 최장 기록, CPU와 예선→결승 |
| 시점 | 사이드뷰 (공이 포물선으로 날고 카메라가 추적) + 좌우 편차용 탑다운 미니맵 |
| 용도 | KLD 홍보·이벤트용 — 타이틀/간판에 KLD 로고, 기록 공유 기능 |
| 스타일 | 가벼운 8비트. 프레임워크·빌드 없음, 순수 HTML/CSS/JS + Canvas + WebAudio |

기본값(설정에서 변경 가능): 거리 단위 yd(필드 장타 대회 표기 관행) / m 전환, 언어 한국어 / 영어 전환.

## 3. 대상 환경

- **모바일 세로 화면이 1순위** (카카오톡·인스타그램 인앱 브라우저). 가로 회전을 요구하지 않는다. PC·가로 화면도 같은 코드로 대응.
- 서버 없이 정적 파일만으로 동작. 공식 배포는 https 정적 호스팅을 전제로 한다.
  `index.html` 더블클릭(file://)으로도 플레이는 되지만 공유할 주소가 없다.
- 저장은 `localStorage` (설정, 최고 기록, 이 기기의 기록 목록, 입력 지연 보정값). 저장소를 못 써도 게임은 돌아간다.
  대회 기록은 **세트가 끝날 때마다** 저장한다. 한 판은 기록 목록에서 한 줄만 차지하고(더 좋은 기록이 나오면 그 줄을 고쳐 쓴다),
  도중에 그만두거나 탭을 닫아도 그때까지의 기록은 남는다. 재도전(CONTINUE)을 써도 줄이 늘지 않는다.
- 무음이 기본 전제다(아이폰 무음 스위치는 WebAudio를 막는다). 모든 타이밍 단서는 소리 없이도 성립한다.

## 4. 게임 규칙

### 4.1 한 세트
- 공 6개, 세트 시계 2:30. 시계는 **첫 스윙을 시작한 뒤부터**, 어드레스·게이지 중에 흐른다.
  공이 나는 시간 몫으로 **임팩트마다 10초를 깎는다**(실제 대회는 공이 떠 있는 동안에도 시계가 간다).
  따라서 실질 여유는 약 90초, 공당 15초. 바람을 기다릴 수 있는 횟수가 세트당 3~4번이라 "기다릴까, 지금 칠까"가 선택이 된다.
- 0초가 되기 전에 시작한 스윙은 끝까지 유효(버저비터). 0초에 어드레스 상태면 남은 공은 사라진다.
- 그리드 폭 60야드. 공이 **최종적으로 멈춘 위치**가 그리드 안이어야 기록 인정. 밖이면 OB.
- 기록 = 인정된 공 중 최장 거리(티에서 멈춘 지점까지의 전방 거리, 0.1 단위 표시). 400야드에는 금색 선이 있다("400 CLUB").

### 4.2 대회 구조 (4라운드, 기본 24구 · 재도전하면 30구)
| 라운드 | 형식 | 분위기 | 바람 | 새로 열리는 것 | 판정 창 |
|---|---|---|---|---|---|
| 예선 | 16명 중 상위 8명 통과. 컷 라인(8위 기록)이 필드에 표시된다 | 아침 | 약한 순풍, 돌풍 없음 | — | ×1.25 |
| 8강 | 1:1 매치 | 한낮 | 옆바람 | 조준 ◀▶, 레드존 2회 | ×1.1 |
| 준결승 | 1:1 매치 | 노을 | 맞바람 + 돌풍 | 탄도 저·중·고 | ×1.0 |
| 결승 | 1:1 매치 | 야간 조명 | 순풍 + 큰 돌풍 (가장 큰 기록이 나오는 라운드) | — | ×1.0 |

- **매치는 실제 장타 대회처럼 진행한다**: 상대(CPU)가 6구를 먼저 다 치고, 그 최고 기록이 "넘어야 할 기록"으로 고정된다.
  플레이어가 그 기록을 넘기는 순간 **워크오프** — 남은 공을 안 쳐도 승리다(남은 공으로 기록 도전을 고를 수도 있다).
- CPU 기록은 라운드 시작 때 확정된다. 플레이어의 샷을 보고 바꾸지 않는다.
- 8강 대진은 예선 순위로 정한다(1-8, 4-5, 3-6, 2-7). 예선을 잘 치면 약한 상대를 만난다.
  본선 인원(8명)은 대진 구조에 묶인 고정값이다(`KLD.tournament.ADVANCE`). 예선 인원은 `config.cpu` 명단 + 플레이어이고,
  CPU는 7명 이상이어야 한다. 라운드 구성(예선 1 + 매치 3)이나 명단이 맞지 않으면 시작할 때 화면에 설정 오류를 띄운다.
- 유효 기록이 없으면 탈락. 둘 다 없으면 재경기(CPU끼리의 경기도 같다). 동률이면 플레이어 승.
  상대가 6구를 전부 놓쳐 기록이 없으면 공 하나만 살려도 워크오프.
- 탈락하면 같은 라운드 재도전 1회(CONTINUE). 그 뒤에는 처음부터.
- **몸풀기**: 첫 방문자는 설명서 대신 2구를 직접 쳐 본다(1구는 느린 게이지 + 반드시 성공, 2구는 실전 속도).
- **연습 모드**: 시계·상대 없이 무제한 타격.

### 4.3 바람
- 라운드별 기본 바람 + 잔물결 + **예고되는 돌풍**(8~14초 간격, 4초 전 예고, 상승 0.8초 · 유지 3초 · 소멸 1.2초).
  돌풍이 순풍 쪽일 확률은 준결승 65%, 결승 50%.
- 바람은 **스윙을 시작한 순간의 값으로 고정**된다(WIND LOCK). 본 바람과 적용되는 바람이 같다.
- 높이에 따라 세진다: 표시 풍속 × clamp(0.5 + 높이/50m, 0.5, 2.0). 그래서 탄도 선택이 의미를 갖는다.

### 4.4 난이도 (CPU 선수와 통과율)
- CPU도 플레이어와 같은 샷 모델·물리로 친다(`simulateCpuSet`). 플레이어와 다른 점은 다음이 전부다.
  - 선수마다 최고 헤드 스피드(134~150mph)가 다르다. 플레이어는 147mph.
  - **크게 빗맞은 공(탑볼·뽕샷, |e| ≥ 1.3)은 기록으로 치지 않는다**(OB 처리). 실제 장타 대회처럼 "여섯 개 중 절반쯤만 들어간다".
    플레이어의 탑볼은 그리드 안에 멈추면 그대로 인정된다.
  - 레드존을 쓰지 않는다(파워 100% 상한). 라운드 판정 창 배율과 완충(연속 실패·마지막 공)도 받지 않는다(항상 ×1.0).
  - 시계가 없다. 공마다 후보 시각 1~3개 중 순풍이 가장 센 때를 골라 친다(`read`가 0.25·0.75를 넘을 때마다 후보가 하나씩 는다).
  - 탄도는 늘 바람에 맞게 고른다(맞바람이면 저, 순풍이면 고 — `pickTraj`).
- 상대의 6구가 전부 무효면 "기록 없음"이다(8강에서 약 6%, 준결승·결승에서 약 3%). 그때는 공 하나만 살려도 이긴다.
- 명단 구성: **보스(킹콩 장, 150mph)** 한 명만 꾸준하고(임팩트 오차 σ 75ms), 도전자 셋(148~149mph)은 크게 치지만 기복이 심하고(σ 200~212ms),
  중위권(144~148mph, σ 178ms)이 예선 컷 라인(평균 약 412yd)을 만든다. 하위권(134~141mph)은 예선을 거의 통과하지 못한다.
  보스가 결승에서 내는 기록의 일부(결승의 약 15%)는 레드존 없이는, 일부(약 11%)는 순풍 돌풍을 기다리지 않고는 넘을 수 없다.
  둘을 다 쓰면 넘지 못하는 판은 없다(게이지의 NEED 표시가 필요한 파워를 알려 준다).
- 난이도는 사람 대신 치는 봇으로 대회를 수천 번 돌려 맞춘다(`node tests/balance.js`, 약 3~4분).
  통과율 = 그 라운드에 올라온 판 가운데 재도전 없이 통과한 비율. 아래는 가상 대회 900개의 결과다(오차 ±1~2%p).

| 봇 (임팩트 오차 σ) | 예선 | 8강 | 준결승 | 결승 | 우승 (재도전 없이 / 1회 사용) |
|---|---|---|---|---|---|
| 초보 (55ms, 늘 20ms 늦다. 파워 95%를 노리지만 들쭉날쭉. 조준·탄도 선택을 안 하고 레드존도 일부러는 안 쓴다) | 83% | 46% | 24% | 13% | 1% / 4% |
| 보통 (40ms, 10ms 늦다. 조준 오차 0.75°, 탄도는 70% 맞게 고름, 마지막 2구에 레드존) | 95% | 71% | 51% | 39% | 13% / 31% |
| 숙련 (22ms. 조준 오차 0.25°, 탄도를 늘 맞게 고름, 뒤지고 있으면 레드존) | 99.7% | 92% | 72% | 62% | 41% / 68% |
| 초보 + 돌풍 기다리기 | 84% | 48% | 42% | 27% | 5% / 12% |
| 보통 + 돌풍 기다리기 (기다린 공은 레드존) | 96% | 71% | 75% | 72% | 37% / 66% |
| 숙련 + 돌풍 기다리기 (기다린 공은 레드존) | 99.7% | 91% | 91% | 91% | 76% / 94% |

  - 위 세 행이 **튜닝 기준**이다. 목표 범위는 초보 80~90 / 38~50 / 22~35 / 10~20, 보통 92~98 / 62~75 / 42~55 / 28~40,
    숙련 99~100 / 85~93 / 68~80 / 52~65 (%). 이 봇들은 어드레스를 마친 순간 순풍 돌풍이 이미 예고돼 있을 때만 기다린다(세트당 한 번쯤).
    여유가 1~2%p뿐인 칸이 있으므로(초보 준결승, 보통 결승, 숙련 8강) CPU 값·돌풍·판정 창을 고친 뒤에는 반드시 전체 표를 다시 돌려 본다.
    `--quick`(약 10초)은 오차가 ±3~6%p라서 크게 어긋난 것만 잡는다.
  - 아래 세 행은 **참고**다. 라운드 안내의 팁("돌풍 예고를 보세요", "순풍 돌풍을 기다렸다가 띄워 치세요")대로 순풍 돌풍이 예고될 때까지
    어드레스에서 기다렸다가 치는 플레이어로, 손은 위 세 봇과 같다. **이 요령 하나로 준결승·결승이 크게 쉬워진다**(시계는 한 번도 모자라지 않는다:
    6구에 90초쯤 쓰고 60초가 남으며, 첫 스윙 전에는 시계가 가지 않는다). 요령을 익힌 사람에게는 8강(조준·옆바람)이 가장 어려운 라운드가 된다.
    이 차이를 줄이려면 보스나 돌풍 크기를 만지는 것으로는 안 되고(재 보았다), 기다림에 값을 매기는 규칙 변경과 전면 재조정이 필요하다 — 열린 결정 사항.
- 손잡이: 보스의 꾸준함(`timingMs`)은 결승과 준결승을 함께 움직인다(준결승 상대의 36~41%, 결승 상대의 55~70%가 보스).
  8강은 도전자 셋과 중위권 상위(캐논·타이탄·로켓)가 반반, 예선 컷은 중위권 값이 정한다. 보스를 1mph만 늦춰도 결승이 7%p쯤 쉬워진다.
  `tests/balance.js`의 `playSet()`은 `js/game.js`의 스윙·시계·완충 규칙을 옮긴 것이라, 그쪽 규칙을 바꾸면 함께 고쳐야 한다
  (실제 `game.js`를 머리 없이 돌려 3,600구를 대조했을 때 차이 0).

## 5. 조작 (탭 세 번)

| 동작 | PC | 모바일 |
|---|---|---|
| 탭 ① 스윙 시작 / 탭 ② 파워 / 탭 ③ 임팩트 | Space · Enter · 클릭 | 화면 탭 (스윙 중에는 화면 전체가 탭 영역) |
| 조준 좌/우 | ← → | ◀ ▶ 버튼 |
| 탄도 저/중/고 | ↑ ↓ | 탄도 버튼(순환) |
| 비행 빨리감기 | 누르고 있기 | 누르고 있기 |
| 음소거 / 일시정지 | M / Esc | 버튼 · 뒤로가기 |
| 메뉴·결과 화면 | 방향키(이동·스크롤) · Enter/Space · Esc | 탭 |

- **일시정지**: 파워를 확정한 뒤(탭 ② 이후)에는 직접 누른 일시정지가 먹지 않는다(공짜 다시 치기 방지).
  화면이 가려져(전화·앱 전환) 자동으로 멈춘 경우에는 진행 중이던 스윙을 취소하고 공과 레드존 횟수를 돌려준다.
- **뒤로가기**: 플레이 중에는 일시정지 메뉴를 열고, 일시정지 메뉴에서는 닫고, 최종 결과 화면에서는 타이틀로 간다. 타이틀에서는 평소대로 페이지를 떠난다.

### 5.1 파워 게이지
- 커서는 처음 0.25초만 가속하고 이후 **등속(초당 100%)**으로 오르내린다. 2왕복 안에 못 누르면 어드레스로 복귀.
- 구간: **SAFE**(90% 미만) / **FULL**(90~100%) / **OVER**(100~108%, 레드존).
- 레드존은 세트당 2회. 108%에서 헤드 스피드 +4%(약 +15yd)지만 판정 창이 가장 좁다. 최장 1구 승부에서는 위험이 공짜라서, 횟수를 묶어 "언제 쓸까"를 결정으로 만든다.
- 30% 미만에서 누르면 취소(공 소모 없음). 헤드 스피드 = Vmax × (0.60 + 0.40·p^1.5), Vmax = 147mph.
- 게이지 위 **NEED** 표식: 지금 바람·조준·탄도에서 정타로 넘어야 할 기록을 넘는 최소 파워.

### 5.2 임팩트 게이지
- 파워 확정 → 0.29초 멈춤 → 커서가 0.75초에 바를 지나간다(**고정 템포**). 스위트스팟은 바의 78% 지점, 거기까지의 절반(바의 39%) 지점에 박자 눈금.
- 판정 창은 ms로 정의한다(오차 e = 1 에 해당하는 시간): SAFE ±150 / FULL ±100 / OVER ±60. 등급: |e| ≤ 0.25 PERFECT, ≤ 0.5 GREAT, ≤ 0.8 GOOD, 그 이상 MISS.
  FULL 기준 PERFECT ±25ms, GREAT ±50ms, GOOD ±80ms.
- **등급이 결과를 약속한다**: 무풍·조준 0 기준 GOOD까지는 그리드 안. OB는 MISS, 옆바람, 조준 실수에서 난다.
- 입력 지연 보정: 탭 시각에서 기본 45ms(터치) / 25ms(마우스·키)를 뺀다. 임팩트 오차의 중앙값이 한쪽으로 쏠리면 라운드 사이에 조금씩 자동 보정한다.
- 입력 잠금: 게이지 시작 후 0.25초, 임팩트는 커서가 바의 25%를 지난 뒤부터, 어드레스 진입 후 0.35초, 오버레이를 닫은 뒤 0.4초.
- 완충: 연속 실패마다 판정 창 ×(1 + 0.12n), 최대 ×1.48. 유효 기록 없이 마지막 공이면 창 ×1.5, 사이드스핀 ×0.6("먼저 하나 살리자").

### 5.3 샷 모델 (입력 → 발사 조건)
| 값 | 식 |
|---|---|
| 볼 스피드 | 헤드 스피드 × 스매시. 스매시 = 1.488 − (빠른 쪽 0.08 / 늦은 쪽 0.12)·\|e\|^1.5, PERFECT ×1.008 (= 정확히 1.50). \|e\| 1~1.3 구간은 1.30 쪽으로 더 줄어든다(실제 최저 약 1.33) |
| 발사각 | 탄도 저 8.0° / 중 12.5° / 고 16.0°, + 0.8°·e |
| 백스핀 | 저 2050 / 중 2300 / 고 2300 rpm, + 300·e (늦으면 스핀이 늘고 빠르면 준다) |
| 출발 방향 | 조준각 + 1.2°·e′ (e′ = e. 단 PERFECT이면 ×0.5, 빠른 쪽이면 ×0.88) |
| 사이드스핀 | 300 rpm · e′ |
| 큰 미스 (\|e\| ≥ 1.3, 탭을 안 하면 e = 1.5) | 빠르면 **탑볼**(볼 스피드 ×0.62, 발사각 3~4.5°, 3800rpm, 약 175yd), 늦으면 **뽕샷**(×0.70, 27~31°, 5200rpm, 약 195yd). 플레이어 공은 그리드 안에 멈추면 인정, CPU 공은 무효 |
| 노이즈 | PERFECT 0배, GREAT 0.5배, 그 외 1배 (같은 입력 = 같은 결과) |

실측(물리 엔진 기준): 풀파워·PERFECT·무풍 ≈ 411yd(세 탄도 동일). 맞바람 4m/s 385/369/357, 순풍 4m/s 434/449/458 (저/중/고).
옆바람 1m/s ≈ 조준 2칸(1°). 미니맵의 + 표시가 "정타로 치면 멈출 자리"를 보여 준다.

## 6. 물리 (`js/physics.js`)

- 좌표: x 전방(m), y 위(m), z 오른쪽(m). 3차원 탄도, 공기 저항 + 마그누스 양력(스핀 비의 포화 함수), 스핀 감쇠, 바람(높이별 배율), RK4 1/240초.
- 지면: 바운드(충돌 속도에 따라 줄어드는 반발, 백스핀에 의한 감속) → 구름(마찰). 그리드 밖(러프)은 마찰이 크다.
- 발사 순간 전체 궤적을 미리 계산해 재생한다 → 결과를 알고 연출(슬로모션, 재생 속도)을 짤 수 있고 결정적이다.
- 보정(무풍·해수면): PGA 투어 평균 드라이버 167mph/10.9°/2686rpm → 캐리 274yd, 총 298yd. LPGA 222yd. 장타 220mph/12°/2200rpm → 캐리 388yd.

## 7. 화면

### 7.1 해상도·배치
- 내부 해상도는 가변. 기기 픽셀 기준 정수배 스케일: `s = floor(min(devW, devH) / 200)`. 단, 긴 변도 본다 —
  세로형은 `floor(devH / 340)`, 가로형은 `floor(devW / 300)`을 넘지 않는다(태블릿·폴더블처럼 정사각형에 가까운 화면 대응).
  그래서 세로형은 내부 높이 340 이상, 가로형은 내부 폭 300 이상이 보장된다. 내부 폭·높이의 범위는 160~480 × 160~560.
- 세로형(H > 1.15·W): 위에서부터 월드(HUD 겹침) → **게이지** → 미니맵 → 버튼. 눈은 게이지에, 엄지는 맨 아래 SWING에.
- 가로형: 월드가 화면 대부분, 하단에 얇은 덱(게이지 · 미니맵 · 버튼).
- 조준·탄도가 잠긴 라운드에서는 SWING 버튼이 그 자리까지 차지한다.
- **플레이 화면은 100% 캔버스**(HUD·게이지·버튼 포함, 좌표 히트테스트). **메뉴·결과·기록·설정·공유는 DOM 오버레이**.
  오버레이의 긴 본문은 스크롤 영역에 넣고 주 버튼은 그 밖에 둔다(어떤 화면 높이에서도 버튼이 잘리지 않는다).

### 7.2 월드(사이드뷰)
- 선수는 카메라를 마주 보고 서서 화면 오른쪽으로 친다. 스케일 가로 1.5px/m, 세로는 화면 높이에 맞춰 0.9~2.6px/m.
- 지면 띠에서 공의 좌우 편차 z는 깊이(세로 위치)로 표현 — 슬라이스는 화면 아래쪽, 훅은 위쪽.
- 50야드마다 표지판과 깃발, 400야드 금색 선, 스폰서 보드(표지판 줄 위, 100야드마다), 관중석, 전광판, KLD 백드롭. 라운드별 팔레트(아침/한낮/노을/야간).
- 선수는 **절차적 관절 모델을 픽셀로 그린다** → 게이지와 스윙이 정확히 동기화되고 백스윙 크기가 파워에 비례.

### 7.3 연출·재생 속도
- 임팩트: 등급별 히트스톱(133 / 83 / 50 / 20ms)·화면 흔들림, PERFECT만 플래시. 직후 **볼 스피드**를 가장 크게 띄운다.
- 비행은 1.5배속. 기록 경신 가능성이 없는 공(OB 확정 또는 15yd 이상 짧음)은 정점 이후 3배속. 누르고 있으면 4배속.
  넘어야 할 기록 근처에서 멈추는 공만 슬로모션.
- 샷 후 **런치 모니터**(볼 스피드 · 헤드/스매시 · 발사각/스핀 · 캐리+런 · 좌우 편차)와 "빠름/늦음 ms". 결과는 2.6초 뒤 자동 진행.
  세로 화면이 낮으면 모니터를 다섯 줄 → 핵심 세 줄 → 두 줄로 줄이고 결과 배너를 위로 올린다. 모니터가 배너를 가리는 일은 없다(`resultLayout`).
- OB는 테두리 플래시 + 부저 + "비공인 357yd". `prefers-reduced-motion`이면 흔들림·전체 플래시를 끈다.
- 색은 파랑·노랑 축과 밝기·무늬(디더)로 구분한다(적록 색각 대응).

## 8. 오디오 (`js/audio.js`)
- WebAudio 칩튠(펄스 2 + 계단식 삼각파 베이스 + 노이즈). 외부 음원 없음. 효과음 22종(+ 게이지 연속음), 음악 4곡(title/play/result/champion).
- 게이지 커서를 따라가는 연속 음, 50야드 표지판마다 한 음씩 올라가는 틱(400야드에서 옥타브).

## 9. 브랜딩 · 공유
- 로고: 공식 로고 PNG에서 만든 픽셀 스프라이트(`js/logo-data.js`, `KLD.logo`). 자세한 내용은 `docs/LOGO.md`.
- `js/config.js`에서 광고판 문구, 공유 주소·해시태그, KLD로 나가는 버튼(cta), 분석 훅(track), 규칙 값을 바꾼다.
- **기록 카드**(1080×1350 PNG): 로고, 결과, 거리(두 단위), 볼 스피드·캐리, 400 CLUB 배지, 이름(선택), 주소.
  세트가 끝날 때마다 공유할 수 있다(완주자만 공유하게 두지 않는다).
- 공유 사다리: 이미지 파일 공유(Web Share) → 링크 공유·복사 → 카드를 길게 눌러 저장/스크린샷.
- 링크 미리보기(og 태그)는 `index.html`에 직접 적는다. 배포 시 절대 주소로 바꿀 것.

```
index.html

js/i18n.js        문자열(ko/en)
js/storage.js     localStorage 래퍼
js/px.js          픽셀 그리기 도구, 수학 유틸, 시드 난수
js/text.js        픽셀 텍스트(내장 5x7 비트맵 폰트 + 웹폰트 글리프 캐시)

js/physics.js     탄도 시뮬레이션 (DOM 무관)
js/shot.js        게이지 입력 → 발사 조건, 바람 모델
js/tournament.js  라운드·CPU 선수·대진
js/audio.js       칩튠 엔진

tests/            Node로 돌리는 테스트 (physics, audio, logo, shot, balance)
```

모듈 패턴(전 파일 공통): 일반 `<script>` + `KLD` 전역 네임스페이스, Node에서는 `module.exports`. (`game.js`는 DOM이 있어야 스스로 부팅한다.)

상태 흐름: `TITLE(데모) → (몸풀기) → ROUND_INTRO → address → power → top → downswing → hitstop → flight → result → (다음 공 | 워크오프 | 세트 종료) → ROUND_RESULT → (다음 라운드 | 최종 결과) → 공유`

테스트용 훅: `KLD.game.debug` — 가상 시계(`virtual`, `step`, `runUntil`), 라운드 건너뛰기(`jump`), 지정 샷(`shoot`).
